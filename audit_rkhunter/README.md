# ГК ППК — офлайн-аудит rkhunter + Lynis

Python 3.9+, без внешних зависимостей. Серверы не опрашивает и не изменяет.

## Использование

Разместите `.txt` или `.log` в папке `input` рядом с `audit.py` (регистр имени файла не важен).
Названия: `<hostname>_rkhunter_<suffix>.txt` и `<hostname>_lynis_<suffix>.txt`.

```powershell
.venv\Scripts\python.exe audit.py
```

Скрипт допускает только Lynis, только rkhunter либо обе группы. Если есть повторные файлы Lynis одного hostname, выбирается отчёт с самой поздней меткой `report_datetime_start` (при равенстве — по имени файла); это не сравнение динамики.

## Выходные данные

- `reports/<hostname>_lynis_audit.md` и `.txt` — **отдельный отчёт Lynis** с каждым `warning[]` / `suggestion[]`, рекомендацией и номером строки.
- `reports/00_lynis_summary.md` / `.txt` и `00_lynis_results.json` — общая сводка Lynis.
- `reports/<rkhunter filename>_audit.md` / `.txt` — прежний отчёт rkhunter и корпоративная таблица.
- `reports/00_summary.md` / `.txt` и `00_results.json` — прежняя сводка rkhunter.

## Правила

- `rules.json` — прежние шаблоны rkhunter.
- `ppk_linux_rules.json` — корпоративные требования из `linux.md`.
- `lynis_rules.json` — отдельная база приоритетов и рекомендаций по Lynis test ID.

Для корпоративной проверки Lynis использованы только `details[]=KRNL-6000|sysctl|...;field:...;value:...;`, где Lynis приводит измеренное значение. Если значение в журнале не указано, выдаётся `NOT_CHECKED`. `REVIEW` используется для `kernel.unprivileged_bpf_disabled=2`, которое нельзя механически признать несоответствием требованию `=1` без проверки поведения ядра.

**Ограничения:** `Hardening Index` — собственный показатель Lynis, не процент CIS. `warning[]=PKGS-7392` не раскрывает список CVE. Проверки OWASP и полный CIS Benchmark не подтверждаются выводом Lynis; нужны отдельные наборы правил и данные. Не следует считать `ssh.service=disabled` доказательством отсутствия работающего SSH: возможны socket activation и альтернативные механизмы.

## Разделение по датам

Не сопоставляйте отчёты Lynis от 12 октября 2026 с более ранними rkhunter как единый моментальный снимок. Каждое заключение содержит исходный файл, а для Lynis также дату проверки.

## Дополнительная папка `evidence/`

В прежнем модуле rkhunter сохранена опция `--evidence` для JSON-снимков. Отчёт Lynis отдельно использует только факты из файла Lynis; перенос фактов в JSON без указания происхождения не производится.

## Исправление обнаружения rkhunter (v3)

При запуске скрипт печатает список всех распознанных входных файлов и счётчик по типам.
Теперь поддерживаются вариации имени (`server-rkhunter.log`, `server_rkhunter.txt`, `rkhunter.txt`, `server_rjhunter.log`) и определение по содержимому, если в имени нет слова `rkhunter`. Файлы любого типа должны лежать в `input` рядом со скриптом. Неизвестные `.txt/.log` перечисляются как пропущенные.

Для предсказуемости используйте имена вида `<hostname>_rkhunter_<timestamp>.txt` и `<hostname>_lynis_<timestamp>.txt`.
